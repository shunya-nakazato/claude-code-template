# Claude Code Template

Claude Code を活用した開発プロジェクトのテンプレートリポジトリ。

## 始め方

1. このテンプレートからリポジトリを作成する
2. Claude Code を起動し `/setup` を実行する
3. 対話形式でプロジェクトのルール（技術スタック、コーディングスタイル等）を設定する
4. 設定が完了したら開発を開始する

## 構成の概要

- `CLAUDE.md` — Claude Code が参照するメインの設定ファイル
- `.claude/rules/` — プロジェクト全体の不変ルールを定義するファイル群
- `.claude/skills/` — ワークフローを自動化するスキル（`/commit`, `/plan-review` 等）
- `.claude/hooks/` — ツール実行前にコマンドを検査するフックスクリプト（Bash コマンド検査、commit 前の gitleaks 秘密情報スキャン）
- `.gitleaks.toml` — gitleaks の設定（デフォルトルール + 誤検知の許可リスト）。スキャンは Docker コンテナで実行するため Docker の起動が必要
- `.claude/plans/` — タスクごとの詳細プラン（gitignore 対象、`.gitkeep` のみ追跡）
- `.claude/tasks/` — タスク一覧（gitignore 対象、`.gitkeep` のみ追跡）
- `.claude/lessons.md` — 開発中に蓄積する学びの記録
- `docs/` — 開発中に成長するドキュメント

## 情報の置き場所と役割

「何を・どこに書くか」を以下のように使い分ける。スコープが狭く・変更頻度が高いものほどコードの近くに、広く・安定したものほど上位のドキュメントに置く。

| 置き場所 | 役割 | 記載するもの | 変更頻度 |
|---|---|---|---|
| `.claude/rules/` | プロジェクト開始時に決める不変のルール | 技術スタック・コーディング規約・命名規則など、開発期間を通じて変わらない方針。`/setup` で初期設定する | 低 |
| `.claude/lessons.md` | 作業を進める中で得た教訓 | 修正を受けて学んだこと・踏んだ罠・再発防止策。気づくたびに追記する | 高 |
| `docs/` | 設計・実装の根拠 | アーキテクチャ、設計判断の why、トレードオフ、非自明な UX 仕様。コードから自明な内容は書かない | 高 |
| git commit メッセージ | その変更時点の根拠 | `docs/` と同様に「なぜこの変更をしたか」。**直近の変更を時系列で追える**のが強み | 変更ごと |
| コードコメント | 実装単位の細かい why | 各コード片がなぜその実装になっているか。最も狭いスコープの根拠 | 変更ごと |

### 使い分けの指針

- **rules と docs**: rules は「変わらない決まり」、docs は「変わりうる設計の根拠」。同じ規約でも、開始時に固定するなら rules、運用で育つなら docs。
- **docs と commit メッセージ**: どちらも「根拠」を残すが、docs は現時点のあるべき姿を俯瞰でき、commit メッセージは変更の履歴を時系列で追える。両者は補完関係にある。
- **commit メッセージとコードコメント**: commit は「変更（差分）の why」、コードコメントは「その場に居続ける実装の why」。レビューや過去調査では commit を、コードを読む人にはコメントを向ける。
- **lessons.md**: 上記が「成果物に対する記録」なのに対し、lessons.md は「進め方・働き方に対する記録」。同じ失敗を繰り返さないための運用メモ。
